# CodeTrail 0.3.0 命名迁移

自 0.3.0 起，产品统一使用 **CodeTrail**。0.1.0/0.2.0 中的 CodeGraph 名称改为以下入口；本版本不提供旧名称别名。

- CLI：`codegraph` → `codetrail`；Windows 预编译包入口为 `codetrail.cmd`。
- npm 根包：`codegraph` → `codetrail`；工作区包：`@codegraph/*` → `@codetrail/*`。
- MCP 服务/配置：`codegraph` → `codetrail`，Codex 配置表为 `[mcp_servers.codetrail]`。六个工具名及参数保持不变，只读指引资源为 `codetrail://guide`。
- Skill：`codegraph-understand` / `codegraph-impact` → `codetrail-understand` / `codetrail-impact`，元数据中的 MCP 依赖同步改为 `codetrail`。
- 忽略文件：项目根的 `.codegraphignore` → `.codetrailignore`。内容仍使用相同忽略语法；内置忽略目录改为 `.codetrail`。
- 环境变量前缀：`CODEGRAPH_` → `CODETRAIL_`。包括 `OPENAI_API_KEY`、`OPENAI_MODEL`、`OPENAI_BASE_URL`、`OPENAI_REASONING_EFFORT` 后缀，以及验收脚本的 `BROWSER_CHANNEL` / `CODEX_EXE` 后缀。
- Windows 默认数据基目录：`%LOCALAPPDATA%/CodeGraph` → `%LOCALAPPDATA%/CodeTrail`，独立工作台使用 `cache`，MCP 使用 `mcp-cache`；其他平台仍在 `~/.local/share/CodeTrail` 下。
- 浏览器会话键改为 `codetrail.session`；新的工作台会话链接会写入新键。
- 预编译包改为 `codetrail-mvp-0.3.0-win32-x64.zip`，验证临时目录和演示标识也改用新前缀。

标准供应商环境变量 `OPENAI_API_KEY` 保持可用。专用密钥变量现为 `CODETRAIL_OPENAI_API_KEY`，优先于标准变量；模型配置为 `CODETRAIL_OPENAI_MODEL`。服务仍直接读取进程环境，不自动加载 `.env`。MCP 模式本身不调用模型。

## 更新现有项目

1. 停止旧服务，将项目自己的忽略文件重命名为 `.codetrailignore`，保留原有内容；若两种文件均存在，先人工合并规则。
2. 源码安装执行 `npm ci --ignore-scripts` 和 `npm run build`，更新工作区链接与命令入口。旧预编译包保持原状，请将新包解压到新目录。
3. 更新终端或启动脚本中的项目专用环境变量与 CLI 名称。独立浏览器界面用新的完整会话链接重新打开。
4. 执行 `node scripts/setup-codex.mjs "你的项目目录" --out "新的接入包目录"` 生成配置。停用旧 MCP 配置，将新配置合并到宿主，并用新 Skill 文件夹替换旧 Skill。不要同时加载两套 Skill。
5. 重新加载宿主，确认服务名为 `codetrail`、两个 Skill 为 `$codetrail-understand` / `$codetrail-impact`，六个工具可用。先检查返回的项目根目录，再开始查询。

生成器不修改用户的全局或项目宿主配置；已有配置和缓存也不会自动删除。旧默认缓存留在原目录，包含旧快照、源码及阅读状态，新默认目录首次运行重新分析。若主动复用旧 `--data-dir`，先备份并刷新分析和 Git 比较；分析器版本已更新，不应沿用旧结果作当前证据。

历史阶段验证记录中的旧安装包文件名、路径和 SHA-256 保留，用于识别当时实际验收的产物。它们不是当前安装入口，也不应通过改文件名假装成 0.3.0 的验收结果。本次更名后的验收另见仓库中的 [命名迁移验证记录](https://github.com/jinyangtang33-sys/CodeTrail/blob/main/docs/命名迁移验证记录.md)。
