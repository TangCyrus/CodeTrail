# CodeGraph 第四阶段验证记录

日期：2026 年 11 月 6 日

完成固定 HEAD 基线、工作区双快照、旧新文件/符号映射，以及带改动范围、分版本源码证据和关联路径的潜在影响分析。比较独立于普通架构分析，不要求配置 AI。

## 比较口径与 Git 读取

比较 HEAD 对应的提交内容与解析器读取的工作区当前内容，包含已暂存、未暂存以及纳入范围的未跟踪源码。所选子目录限定源码边界；仓库根目录只用于读取 Git 元数据。

`git.ts` 使用参数数组调用 Git，不经 shell，禁用可选锁、fsmonitor、外部 diff、textconv、替换引用、交互提示和按需远程对象获取。目标仓库不执行初始化、检出、提交、切换分支或依赖安装。

先固定提交 OID，使用 NUL 分隔的 `ls-tree -r -l -z` 读取对象清单，再通过 `cat-file blob <OID>` 读取普通文件。只在工具新建的临时目录写入源码、JSON 和忽略配置；不创建历史符号链接、不恢复执行权限，也不执行目标配置脚本。

**不对工作区执行 Git diff。** 即使关闭外部 diff/textconv，工作区 diff 仍可能调用 clean 过滤器。重命名提示使用 `diff --cached --no-ext-diff --no-textconv --name-status -z --find-renames=50%`，只比较已存储的 HEAD/索引对象；实际改动仍由当前源码快照决定。未暂存且内容同时变化的移动可能显示为删除和新增。

每条 Git 命令超时 15 秒，清单输出最多 8 MiB；历史物化最多 2,000 个候选文件、合计 64 MiB，单文件 1 MiB。解析沿用每侧最多 500 个源码文件。跳过与预算限制进入结果说明；读取失败保留上一份结果。结束或取消时清理本次临时目录。

官方语义依据：[git-diff](https://git-scm.com/docs/git-diff)、[git-ls-tree](https://git-scm.com/docs/git-ls-tree)、[git-cat-file](https://git-scm.com/docs/git-cat-file)。本机验证版本为 Git 2.55.0.windows.5。

## 旧新映射与变化范围

同路径文件先配对，文件变化再比较声明。符号以完整名称、种类唯一匹配，独立于偏移和节点 ID，因此前方插入内容不会使后方未变函数变成新增/删除。分别标记实现、签名、导出和路径变化；未匹配的声明保留新增/删除，歧义不强行合并。

文件重命名由暂存区 Git 相似度或唯一原文哈希匹配提供候选，不等同于语义确认。一侧因忽略、大小、链接或扫描范围未进入解析时标为“范围变化”，不把它当作确定新增/删除，也不生成完整的该文件历史影响。

行范围使用先去公共前后缀的有界 LCS。超过 1,000,000 个计算单元或 100 个改动块时退回文件级范围，并显式标记。只改变换行编码的文件不计为代码变化，缓存和证据继续保留各自原文、哈希与 UTF-16 位置。

每个文件最多展示 500 条声明映射，最多选择 200 个声明/文件起点；达到限制会提示。配置输入不同会说明可能影响未发生源码文本变化的解析结果，本版不穷举配置导致的全部语义变化。

## 路径与源码证据

旧、新图分别反向遍历静态 `CALLS/RENDERS/REFERENCES/IMPORTS`。删除及断开的关系仍能从旧图追踪，新关系从新图追踪；不跨版本拼接边。重复调用/引用优先保留一条最短路径，循环去重，默认最多两跳、显示 100 条，并交替分配旧新版显示预算。`REGISTERS_CALLBACK` 不传播为已证明调用。

纯类型依赖默认关闭，可独立开启；路径标明值、纯类型或混合依赖。文件级导入是保守关联。每一步携带该版本的真实边和证据 ID，源码侧栏使用对应版本保存的内容，核对文件、证据/声明/改动范围是否匹配后显示高亮。路径箭头保留“引用者 → 被引用者”的实际方向。

关联测试要求测试路径上的节点存在真实静态关联；测试文件按 `tests/`、`__tests__/`、`.test/.spec` 约定识别。不根据同名文件自动补关联，不运行测试，不宣称覆盖或执行成功。结果始终表示潜在关联，不保证实际故障，也不能证明未列出代码不受影响。

## 服务、缓存与界面

独立 Worker 完成 Git 读取、两侧解析和映射，前端轮询真实阶段并可取消。Worker 结束后才事务发布结果；取消、失败不覆盖上次结果。SQLite 为比较单独保留最近三份完整 bundle，两侧纳入源码、图谱、证据与结果一并保存，不受普通快照的三份清理影响。

新增接口沿用本地会话、Host/Origin 和 CLI 根目录限制：

- `GET /api/git`：基线状态与固定比较口径。
- `GET /api/comparisons/latest`、`POST /api/comparisons`：最近结果及创建任务。
- `GET/DELETE /api/comparison-jobs/:id`：阶段、状态与取消。
- `GET /api/comparisons/:id/impact?includeTypes=...`：默认或含类型的路径投影。
- `GET /api/comparisons/:id/status`：工作区或 HEAD 是否变化。
- `GET /api/comparisons/:id/:side/files/:fileId`：指定版本的只读源码，可按声明、关系或改动块定位。

前端提供变更清单、关联路径、相关测试，支持文件/起点筛选、类型开关、重试、空结果及无基线降级。宽屏默认展示首个变化文件；手机通过明确操作进入单区域源码。每 8 秒检查工作区和 HEAD，过期后保留旧结果；源码面板同步显示过期提示，重复打开同一位置也会重新核实当前匹配状态。

无 Git、Git 不可用或无 HEAD 时，列出当前源码并说明缺少基线，不生成完整历史路径。部分解析、未解析关系、范围变化、截断和两侧依赖环境不同均有可见说明。历史解析不借用工作区未提交的依赖声明，不安装历史依赖，因此复杂类型环境仍可能存在缺口。

## 验证结果

生产构建、61 项 Node 测试和 15 条浏览器流程通过，无跳过。人工标注样例保持一致：导入 13、调用 18、组件使用 1、回调候选 2、指定引用位置 8、未解析位置 6，均无新增 FP/FN；这些指标只代表固定样例。

新增 12 项 Node 测试覆盖：

1. 固定 HEAD、实际暂存/未暂存内容、中文空格路径和未跟踪源码；比较前后 HEAD、索引字节、工作区状态一致。
2. 删除后旧调用者、签名变化、重命名候选、两跳调用者及每一步同版本源码/哈希/位置。
3. 纯类型开关，防止混为值调用。
4. 行号变化后的唯一符号匹配，以及忽略变化不冒充删除。
5. 无仓库与未提交仓库的当前清单和缺基线降级。
6. 子目录边界、环境文件排除、历史符号链接模式不物化和配置不执行。
7. CRLF 行范围、纯增删、有界差异降级。
8. 工作区/HEAD 过期、取消保留结果、临时目录清理、普通快照清理隔离与数据库重开。
9. 仅换行编码变化不制造代码改动。
10. 有意配置 clean/smudge、textconv、外部 diff、fsmonitor 的样例不会写入执行标记。
11. 循环、两跳截断、路径数量限制、旧新版预算及回调候选边排除。
12. API 请求/版本/范围校验、删除后的旧源码、引用高亮、类型投影及普通 latest 指针不被比较覆盖。

新增 5 条浏览器流程覆盖变更/声明/旧新源码、删除关联/两跳/类型/测试路径、过期与取消/重新比较、三个宽度的路径与旧版源码、无提交仓库。既有 10 条架构与 AI 阅读回归继续通过。回归中修正了 AI 启用开关的异步反馈，生成按钮继续等待服务端确认；也修正了重复选择同一源码不刷新匹配状态的问题。

Git 写入仅用于测试或预览新建的独立样例仓库。预览项目明确命名 `git-impact-demo`，并非用户项目的实际改动。该小样例产生 5 个变化文件、7 个变化声明、19 条默认路径、1 个静态关联测试文件；不能据此外推大项目准确率或性能。
