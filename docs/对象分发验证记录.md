## 解析与拒绝依据

新增解析普通对象属性调用的有界来源追踪。接口注解、结构类型和类型断言只提供候选，不能证明实现。可确认的目标来自源码对象字面量、const 绑定及其别名，或具有唯一同步实现和唯一直接返回的新建工厂对象。支持方法、箭头函数、普通函数值及字符串字面量属性访问；工厂可以先用局部 const 保存对象再返回。独立编译环境之间仍按准确声明位置关联，不按接口名或成员名寻找同名实现。

检查对象及 const 别名的使用，目标成员有直接写入、别名写入、解构赋值、动态写入或删除时拒绝补边；未知函数传参、存储、导出、未验证方法接收者等暴露也保留缺口。无关标量字段写入不自动否定其他已知方法。嵌套对象接收者暂不展开，避免漏掉子对象被提取后形成的独立别名。

回调成员、参数对象、条件或多个返回、共享返回、异步/生成器工厂、getter/展开、复杂 this、私有成员及其他未支持来源均保留缺口。单次来源最多 12 层，安全检查最多 128 个别名、1,024 个引用。缓存仅在一次分析内按具体语法节点和来源使用，不在快照间复用；工厂的不同调用实例不混为同一对象。

已有普通对象方法也不能只凭结构类型就补出调用，例如 `receiver: typeof original` 并不证明 `receiver.run()` 调用 `original.run`。这不构成完整类继承分发、队列/容器点集、全程序参数传递或运行时执行证明。

已解析调用沿用 `resolution: value-origin` 和 `supportingEvidenceIds`，指向初始化、别名、工厂返回和具体函数。未确认对象调用增加可选 `reasonDetail`：`code`、中文 `message` 及最多两份拒绝依据 `evidenceIds`。MCP `symbol_context.unresolvedDetails` 和浏览器关系面板保留这些字段；界面可以直接打开“缺口依据”。旧快照没有该字段时仍能读取。

## 保留缺口的实证

核心对象分发没有通过假定某个接口只有一个实现来清零：

- `atom.ts:182` 的 `atom.get()`：`member-written`。`atom.ts:239` 有条件重写 `atom.get = function ...`，不能固定到初始方法。
- `atom.ts:49` 的 `atom._update()`：`receiver-parameter`。它是 reactive system 回调的参数对象，不是某个已确认的 atom 实例。
- `atom.ts:242/261` 的局部 `atom._update()`：对象经其他调用或共享状态暴露，保留 `receiver-escaped`；本轮不证明这些调用不修改成员。
- `atom.ts:195` 的 `e.stop()`：对象方法使用 this，保留 `object-this`。
- `signal.ts:170` 的 `e.fn()`：成员来自回调参数，保留 `member-not-concrete`。

实际 MCP 读取了 `atom.get` 的拒绝依据，普通快照 `snapshot:4e1b75f9116047d4319514d5` 中 `atom.ts` 文件 SHA-256 为 `098dfdf21c63f46eba54e05ca12fd2f29ebbbc971886ac845be0747ab814b92e`。不是仅依据方法名输出的说明。

## 复现

```powershell
npm run check
npm run test:browser
npm run validate:monorepo -- --out artifacts/object-dispatch/self.json
npm run validate:external -- --dispatch --baseline artifacts/object-dispatch/before.json
$acceptance = Get-Content artifacts/external-monorepo/latest.json -Raw | ConvertFrom-Json
node scripts/validate-resolution-reduction.mjs --before artifacts/object-dispatch/before.json --after (Join-Path $acceptance.run snapshot.json) --expect-external-unchanged --out artifacts/object-dispatch/reduction.json
npm run release
npm run verify:release
```

`before.json` 必须是上面指定的 0.6.0 完整快照；全新目录应先按依赖准备说明获取固定提交及锁定声明，不能用不同源码代替。`--dispatch` 验收本轮对象调用和保留缺口；`--core`、默认 shallow canary 继续保留。分析不运行目标代码或上游测试，不访问真实模型服务，不修改当前 Codex 配置。原始工具输出、失败记录和截图保存在忽略的 `artifacts` 中。
