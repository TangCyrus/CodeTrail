# CodeTrail 试用任务卡（参与者）

你会获得一个指定提交的陌生项目，以及工具条件说明。任务用于发现工具和说明中的问题，不评价你的个人能力。可以使用普通搜索、文件与 diff；T 条件另可使用 CodeTrail。不了解或无法证实时请直接说明。先不要阅读主持人评分标准与预跑答案。

每项提交：简短答案、文件与行号、结论所依据的源码、仍不确定的地方，以及信心 1–5 分。使用 CodeTrail 时附 `snapshotId`；比较证据附 `comparisonId`、`side`、文件哈希。普通文件条件记录 HEAD、文件与行号及当前 diff，不能编造工具 ID。输出格式不影响评分。

## T1：理解陌生项目（10 分钟，只读）

CodeTrail 项目：说明 Agent 发起代码理解与改动比较时，主要经过哪些部分。给出至少三个模块/文件的作用、一个进入位置，以及一条可由源码核对的静态调用关系。给出 3–5 步你愿意继续阅读的顺序，并说明理由。

TanStack Store 项目：说明状态核心与框架适配层如何组织。定位一个公共 API 入口，说明至少三个模块/文件的作用，找出一条核心或适配层的实际静态调用关系。给出 3–5 步阅读顺序，并说明理由。库项目可以有多个导出入口，不要求找到唯一 `main`。

两项目都需区分：源码能证实的关系、名称/目录带来的阅读线索、自己的职责推断。若结果部分解析或截断，说明它会影响哪些判断。

## T2：定位修改点（8 分钟，只读）

CodeTrail 项目：假设希望把改动影响分析的路径数量上限从 100 改成 80，保留现有分页能力。找到控制该上限的具体符号与赋值位置，说明为什么修改这里、谁使用它、需要检查什么测试。暂不改代码；注意区分分析路径上限与一次响应的分页大小。

TanStack Store 项目：假设只把浅比较函数最开始的“两个输入是否相同”判断，从 `Object.is` 改成 `===`，其余比较逻辑保持原样。找到具体符号和语句、一个使用位置与可检查的测试文件，说明 `NaN` 和 `0/-0` 可能出现的差异。此改动仅是演练，不表示推荐修改项目行为。

如果图里没有相关测试，请说明原因并用普通文件工具继续核实；“未找到路径”和“没有测试”不是同一结论。

## T3：判断改动影响（12 分钟）

主持人会应用 T2 的单处练习差异，并告诉你修改已准备好。

1. 核实变化文件、具体符号和旧新语句。
2. 给出至少一个可证实的直接调用者；尝试进一步追踪，但不要补造缺失链路。
3. 打开同一版本的调用依据，提出一个有依据的测试检查建议。不能把静态相关测试称为已覆盖或已通过。
4. 说明哪些结果受部分解析、缺失依赖、截断或源码范围限制影响。T 条件下如概览未显示关键链路，尝试按符号聚焦并记录结果。
5. 主持人恢复练习差异后，核实旧报告的过期提示、旧新源码是否仍保留；重新比较确认零改动。C 条件检查恢复后的 diff，并说明普通文件工具能否继续提供练习时的两侧原文。

T 条件可先使用 `$codetrail-understand`，修改准备好后使用 `$codetrail-impact`。比较固定为 HEAD 与工作区；旧侧和新侧的路径不能连接成一条链。分页后仍可能存在分析截断，未列出的路径不能作为“没有影响”的证据。

最后填写[反馈模板](用户试用反馈模板.md)：指出最卡住的一步、一次有帮助的证据和你最希望改进的地方。无需给出积极评价。
