## 问题与实现

原影响概览依次遍历各变化符号，前面的高扇入符号可能占满 100 条路径。浏览器原有文件筛选和 MCP 分页仅处理已经生成的有限列表，不能恢复被省略起点的调用链。上一轮的 cleanup.clearFlags 两跳链只能从保存图中额外核对，没有通过影响列表返回。

本版概览在多个起点及旧新两侧之间轮流分配路径预算。新增符号搜索从比较保存的变化文件中发现完整声明，不受变化摘要和概览起点上限限制；允许选择声明未变的符号，但不将其称作已发生变化。选中准确版本及 ID 后，从该侧保存的完整图独立追踪，不筛选旧概览，也不拼接两侧关系。

浏览器“改动影响 → 关联路径”提供名称/路径搜索、旧新版本选择、结果翻页、聚焦状态和“返回概览路径”。MCP 继续保持六个工具，在 compare_worktree 增加 symbolQuery/symbolSide/symbolOffset 及 focus 参数；配套改动影响 Skill 同步说明查询方法。查询固定 comparisonId，翻页保持 focus 与 includeTypes；切换符号重置 pathOffset。无 HEAD 仍明确降级，不生成虚构历史影响。

每次查询仍最多两跳、100 路径、20,000 次边检查，概览每侧最多 200 个起点。每个起点/目标保留一条最短依据，不枚举所有可选调用链。truncation 的 changes/seeds/paths/depth/work 分别表示变化摘要、起点、路径、深度及工作量限制；analysisTruncated 表示分析限制，pageTruncated 表示本次返回仍有省略，overviewTruncated 保留整体概览状态。兼容 truncated 汇总限制，分页结束不等于分析完整。

浏览器实测另外发现：自定义缓存放在项目内时，旧版临时源码可能被新版扫描，导致虚假变化与立即过期。比较工作器现于旧版捕获完成后、扫描当前内容前清理临时目录；仅保留已捕获的快照和源码。最终清理及取消保护继续保留。专门回归检查新版没有缓存内临时源码、结果不立即过期，旧侧证据仍可阅读。

本次聚焦的 overviewTruncated 为 true；truncation.depth 为 true，changes/seeds/paths/work 均为 false。两跳内的关键链可见，第三跳之外仍明确保留深度限制，不宣称已取消所有截断。原文 signal.ts 哈希 `6d930397e6287d466aa070851d4dbcd30de1fcce63658c75ca81adffe8f7f07d`，受控样例 `788a22c844b8117fc92e90dec5a3b41567f6ddfc14ab1eb4cb20d97bc7c8c433`。finally 按原字节恢复，Git 确认验收克隆干净。
