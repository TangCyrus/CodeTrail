# CodeTrail 小范围用户试用方案

适用版本：0.10.0。状态：已准备试用材料与工程预跑，尚无真人参与者结果。工程脚本、模型回复和主持人的预演都不能填写为用户成绩或满意度。

## 使用这套材料

1. 主持人先读本方案和[验收与评分标准](试用验收标准.md)，核对目标提交、接入与声明依赖环境。
2. 只向参与者发[任务卡](试用任务卡.md)和[反馈模板](用户试用反馈模板.md)。评分标准中的参考位置在交卷前不展示。
3. 每人每个条件复制一份反馈模板；原始答案、耗时、帮助次数和证据原样保留。不要预填成功、分数或改善比例。
4. 工程准备情况见[预跑记录](试用预跑记录.md)。在完整源码工作区重新准备环境后运行 `npm run validate:trial`，产物保存在 `artifacts/user-trial`，不混入真人记录。预编译 ZIP 包含试用文档，但不包含开发验收脚本、外部克隆或真人数据。

## 招募与分配

第一轮计划 3 位新手、3 位熟练开发者，使用匿名编号 N01–N03、E01–E03；编号只是分配计划，不表示已招募。参与者需未读过对应项目，记录 TS/JS、Git 和 Agent 使用经验及项目熟悉程度；熟悉项目者另记为探索性试用，不并入陌生项目对照。

固定两个项目：A 为 CodeTrail（本轮参考 HEAD `4407f7510c21d1b3d1d46df5940b6219290966f2`）；B 为 TanStack Store（`53f30be1e43c8d7899ace08023705b34f5e533f8`）。主持人使用专用试用副本，不在参与者日常工作区施加练习改动。CodeTrail 在发布材料后有文档提交，实际试用仍先记录、核对选定源码提交；更换源码版本时重新预跑和核对参考答案。

条件 T：在 Codex 中使用 CodeTrail MCP 与两个 Skill，可同时用普通搜索、文件和 diff 工具；条件 C：相同 Codex 版本、模型及参数，只使用普通搜索、文件与 diff，不提供 CodeTrail MCP、Skill、缓存输出或本项目参考答案。工作台为 T 条件可选的证据入口。两条件都关闭独立工作台的按需 AI，宿主模型保持一致。未能保持同模型/配置、没有控制条件或发生网络故障时，记录偏离，不合并计算效率改善。

预定分配如下，主持人须记录实际执行情况：

- N01、E01：A/T → B/C。
- N02：B/C → A/T。
- E02：A/C → B/T。
- N03：B/T → A/C。
- E03：A/C → B/T。

工具优先与直接阅读优先各三人，A、B 各在 T、C 条件出现三次。项目与顺序交错但六人不足以消除所有差异，应按项目、经验和顺序分别查看结果；不能直接把两个不同项目的耗时当成同等难度的个人改善率。同一个人不在同一项目重复两条件，以减少答案记忆影响。

## 单个条件的执行

接入检查与中性操作练习约 5 分钟，使用独立小样例，不提前展示任务答案。升级后先重载 MCP；仅“刷新分析”不会重载常驻服务。核对服务版本、项目根目录，刷新后确认 `stale: false`，不能带着过期结果进入任务。记录安装、首次分析等待和主持人帮助，安装时间单独统计。若接入失败，先按阻断规则处理，不把安装失败计作用户不理解代码。

正式任务按 T1 → T2 → T3：理解陌生项目 10 分钟、定位修改点 8 分钟、改动影响分析 12 分钟。时间从发出该任务卡开始，工具/模型等待计入任务时间，暂停及原因另记。完成后记录实际秒数；超时记录实际时限、`timeout` 和已完成部分，不能填 0 秒或按成功任务计算速度。两条件之间休息，单人完整试用约 70–80 分钟。

T1、T2 先只读。T3 由主持人应用任务卡指定的一处练习差异，保存原文字节；不让参与者额外编写实现，以免写代码能力主导阅读评估。结束后仅在内容仍为练习差异时恢复，不覆盖并发修改；重新比较确认零变化。分析不会执行目标项目，练习不提交给上游。

允许主持人解释操作方式；任何提示均逐次记录。提示具体文件、符号、答案或代操作后完成标为 `assisted`，不能算作独立完成。新手可用自然语言描述，熟练者可直接引用调用点，正确性标准相同。参与者可以表达“不确定”，不鼓励编造链路。

## 收集与决策

以[反馈模板](用户试用反馈模板.md)为主记录，每任务包括答案、状态、耗时、0–4 分评分、证据身份、帮助与问题。既有 `用户试用记录模板.csv` 可选作汇总索引：`max_score` 填 4，`notes` 指向完整反馈；旧版 0–3 分记录不得直接混算，完整证据和问题仍保存在反馈模板中。当前 CSV 仅有表头，没有已完成参与者数据。

分别统计各项目、经验组、条件的独立完成率、评分和成功任务中位耗时；同时列出超时/阻断数量，不能通过排除失败样本宣称整体变快。首轮是寻找高频卡点的小样本研究，不计算统计显著性，不承诺准确率或 30% 耗时改善。正负面原话均保留，经同意后才保存截图、聊天或源码片段；不记录真实姓名、API 密钥或工作台会话链接。

邀请前必须达到工程准入标准；真人结束后按评分标准决定继续试用、优先修复或暂停扩大。没有通过不是要求放宽断言，而是形成具体、可复现的问题。优先级以阻断任务和误导结论为依据，不以新增关系数量替代用户效果。

## 独立的 AI 质量评测

`AI解释评测样本.json` 继续用于真实模型的单独评测，记录模型、配置、实际发送范围、输出、延迟和用量。引用身份有效与人工核对的语义支持率分别统计。首次工程预跑不调用模型，不能证明宿主自主选工具、Skill 行为或解释质量；正式试用通过实际聊天记录观察这些行为，并记录人工纠正次数。
