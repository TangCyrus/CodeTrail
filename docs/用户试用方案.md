# CodeGraph MVP 用户试用方案与记录

状态：方案已准备，尚未邀请参与者，当前没有真人试用结果。下列编号和条件仅用于组织后续试用，不能作为用户反馈。

## 对象与顺序

计划至少 3 位新手、3 位熟练开发者。选择参与者未接触过、语言和规模接近的两个项目 A/B。每人完成工具阅读与直接读代码两个条件，分配不同项目，避免重复阅读同一项目造成学习偏差。

六人总体按 3 人工具优先、3 人直接阅读优先平衡。新手组可按 2/1 分配，熟练组按 1/2 反向分配；项目 A/B 同样交错，实际分配写入记录。首次比较关闭 AI，以免账户模型、网络和解释质量成为混杂因素。

## 四类任务

每项设置统一时限，记录未完成而不是填零秒。主持人预先核对参考答案、位置和允许的多种合理回答。

1. 找入口：指出至少一个进入位置，说明依据是命名候选、静态使用还是实际启动代码。
2. 描述模块：说明两个目录/文件的职责依据，区分目录聚合和业务边界推断。
3. 追踪关系：从指定函数或组件给出一条真实调用/使用路径，并打开具体源码位置。
4. 判断修改关联：对一处签名修改或删除，指出一个直接/间接对象、一个相关测试依据或明确的未发现情况，并说明分析缺口。

每项可按 0–3 分记录：0 无法完成，1 仅定位，2 解释与源码基本一致，3 依据完整并正确说明候选、类型、旧新版或未解析边界。评分不要求使用特定术语，不奖励把未知行为说得确定。

## 记录与判断

使用相邻的 CSV 模板记录参与者匿名编号、经验组、项目/条件/顺序、任务耗时、完成状态、得分、打开证据次数、信心和问题描述。不要先填写预期改善数字。

分别报告新手、熟练组及总体的中位耗时、正确性和完成率。未完成任务保留时限与状态，不能用零秒拉低耗时。约 30% 的中位耗时改善是探索目标，理解正确性不能下降；六人小样本不作统计显著性结论。

在真实试用后整理：最常卡住的步骤、误解的标签、推荐是否有帮助、源码证据是否充分，以及需要优先修复的核心流程问题。若价值没有出现，优先调整导航和解释，再扩展功能。

## AI 单独评测

`AI解释评测样本.json` 保存固定问题、参考事实和禁止无依据扩大之处。配置真实模型后再保存实际输出，分别统计有效引用率与人工语义支持率；推断标记和信息不足另记。

引用 ID 可自动校验，语义评分需逐条对照实际发送的片段。未测条目不得填入分数或成功率。模型、配置、输入摘要、时间、延迟和用量都应随真实评测记录；本地模拟回复不计入质量结果。
