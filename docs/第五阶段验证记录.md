# CodeTrail 第五阶段工程验收记录

日期：2026 年 11 月 6 日。版本：MVP 0.1.0 本地试用候选版。

本轮完成代表样例的端到端验收、重复性能测量、失败场景验证、核心问题修复和 Windows 本地包交付。结论限于工程与自动验收，真实用户效果和真实模型语义质量尚待测量。

## 代表项目与依据

仓库 `examples/` 新增三个固定项目，全部由本项目为验收编写，不冒充独立团队代码：

- `react-checkout`：7 个文件，32 个符号，76 条关系、74 个证据。验证 `App → CheckoutForm` 的静态组件使用和 `createOrder → calculateTotal` 的直接调用；最小 JSX 声明只用于静态阅读。
- `ts-inventory`：6 个文件，16 个符号，46 条关系、45 个证据。验证入口、转导出、`checkout → reserve`、模型类型与测试文件关联。
- `git-alias`：7 个当前源码文件。工具在新目录建立独立演示仓库，包含 TS 路径别名、暂存与未暂存、删除、重命名候选和未跟踪源码。当前结果为部分解析，因删除而断开的引用被如实保留；旧版 `legacyDiscount` 的调用证据仍可打开。

三个项目均通过“概览 → 搜索 → 局部图 → 源码证据 → 阅读推荐/清单 → 本地解释 → 重开后恢复进度”的 API 与浏览器流程。每条已保存证据的原文、UTF-16 偏移和文件哈希逐项核对。Git 样例另验证旧新版路径、静态关联测试及删除后的旧源码。

代表项目的断言只覆盖列明的预期关系和任务闭环，没有为全部关系建立人工金标准。人工标注的完整/指定位置比对仍来自原 `reference-lab`：导入 13、调用 18、组件使用 1、回调候选 2、指定引用位置 8、未解析位置 6，均无新增 FP/FN；不能外推真实项目总体准确率。

## 本轮修复

1. 非法 UTF-8 原先被替换解码，导致原字节哈希与保存字符串不一致，整份快照发布失败。现在扫描阶段明确跳过并给出中文诊断，健康文件继续发布；BOM、CRLF 和 UTF-16 证据仍保留。
2. 损坏的缓存 JSON 或 SQLite 文件原先缺少恢复指引，部分启动失败路径也未关闭数据库。现在关闭已分配资源，并提示使用新的 `--data-dir`；不自动删除旧数据。
3. 自动布局原先在浏览器主线程运行，100 节点稠密样例会长期阻塞页面。现在移入可中止 Worker，2 秒超时、加载失败或无响应时终止并回退网格；切换视图取消旧工作。
4. 初次 ResizeObserver 通知可能再次 fitView，覆盖用户刚做的缩放。现在仅在真实尺寸变化时适应画布。
5. 安装包首次完整性验证发现打包器对不能由本机代码页表示的文件名发生替换。现在通过系统 ZIP 库显式写入 UTF-8，解压后逐文件校验，包含第三方依赖的 Unicode 文件名。

## 性能方法与实测

硬件与软件：Windows 11（10.0.22631）、Intel Core i7-14700、28 个逻辑处理器、约 31.7 GiB 内存，Node v24.20.0、npm 11.19.0、Git 2.55.0.windows.5。机器不是独占环境，不清空操作系统文件缓存。

每种输入测 3 个新 Node 进程。首次分析包含 Worker、SQLite 保存和第一次概览；另记录完整进程墙钟时间。缓存服务重开 3 次；搜索和一/两跳 HTTP 查询各先预热 5 次，再记录 40 个样本。峰值 RSS 包括 Node 内的 Worker 线程，不含 Git 子进程。输入快照 ID、文件数、行数、字节和原始样本均保存在 JSON 中。

- 100 文件 / 2,577 行合成项目：首次分析 918–1,011 ms，缓存重开中位数约 115 ms，搜索及两跳查询 p95 约 16 ms，冷启动 Node 峰值 RSS 约 331 MiB。
- 500 文件 / 12,977 行 / 381,359 字节合成项目：首次分析 1,973–2,088 ms，缓存重开中位数约 331 ms，搜索 p95 16.228 ms，一跳 16.220 ms、两跳 16.197 ms；阅读推荐 p95 约 110 ms。冷启动 Node 峰值 RSS 约 466 MiB。
- 工具自身：53 个文件 / 3,795 行，首次分析 3.59–3.97 秒，缓存重开中位数约 282 ms，搜索/两跳 p95 约 16 ms，峰值 RSS 约 634 MiB。由于项目引用等边界，该输入为部分解析，不能把完成索引等同于完整自举语义。
- Git 双图单独测量：100 文件三次约 4.37、4.57、4.64 秒；500 文件三次约 19.57、20.14、25.21 秒，峰值 Node RSS 约 617 MiB。它包含历史对象读取和两侧解析，不计作缓存查询延迟。

这些输入全部满足本轮门槛：首次分析 60 秒内，已有快照搜索和一/两跳查询 p95 1 秒内，图投影不超过 100 节点。500 文件只代表约 1.3 万行的本次合成工作负载，不保证任意 500 个大型/复杂文件都有相同表现；3 次启动样本也不足以描述尾部稳定性。

浏览器另测 100 节点、含高扇出关联的样例：修复后布局约 400 ms，测试窗口内最大动画帧间隔约 30 ms；缩放、切换列表和源码选择可用。门槛为布局 5 秒、最大帧间隔 1 秒。单个样例不代表所有稠密图的可读性；超时后仍可使用网格和列表。

## 失败与回归

`npm run check` 通过 70 项 Node 测试和人工标注样例验证；`npm run test:browser` 通过 20 条流程。新增覆盖非法编码、超大文件、端口占用、不可用缓存路径、损坏缓存 JSON/SQLite、AI 连接失败和不可读 Git 元数据；既有语法错误、缺失模块、无 Git/无提交、取消、引用伪造、超时及保留旧源码验证继续通过。

浏览器实际模拟布局脚本加载失败、布局 Worker 无响应和源码 HTTP 503。可以回退、取消未完成布局或重试，不会把失败伪装成完成。正常小项目仍使用真实层级布局；代表项目和原有桌面/平板/手机流程继续通过。

## 安装交付与复现

提供 Windows x64 预编译 ZIP，包含生产依赖、物化后的工作区包、前端/Worker 资源、三个代表模板、安装说明、已知限制、用户试用模板和固定 AI 评测问题。需要本机 Node.js 24.x；Git 对架构阅读是可选的。

`release-manifest.json` 记录逐文件 SHA-256，压缩包路径与整体校验值在 `artifacts/releases/latest.json`。`npm run verify:release` 在工程之外的中文空格临时目录完整解压，清除 NODE_PATH/NODE_OPTIONS，不运行 npm 安装或构建，再验证 Windows 启动器、CLI JSON、Git 演示、双快照路径及浏览器旧版源码。最终结果以 `release-smoke.json` 的通过状态为准。

最终冒烟已通过：4,684 个文件逐一校验一致，安装目录位于原工程之外，CLI、Windows 启动器及 Git/浏览器流程可用，浏览器观察到的外部请求为 0。ZIP 为 19,951,496 字节，SHA-256 为 `957137c6547f201a8eb2e628878c5baaeb29f1398d310017661b6c20929f5e12`。包包含 Node 生产依赖，仍需本机 Node.js 24.x。

对安装包启动的界面，在三个视口下核实变化清单、关联路径与源码共九个状态。设计探针无 FAIL，有 1 项宽屏短路径文本的留白 WARN；截图核实没有重叠、横向溢出或交互阻塞。该非阻断提示保留在 `design-check/report.json`，未将它隐藏或记为零警告。

可复现命令：`npm run check`、`npm run test:browser`、`npm run benchmark`、`npm run release`、`npm run verify:release`。性能和浏览器产物位于 `artifacts/phase-five/`，默认不纳入版本控制；安装与能力边界分别见相邻的《MVP安装说明》《已知限制》。
