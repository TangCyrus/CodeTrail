# CodeTrail 0.6.0：核心调用与外部引用

日期：2026-11-06。继续使用 [TanStack Store 固定提交](https://github.com/TanStack/store/tree/53f30be1e43c8d7899ace08023705b34f5e533f8)，Windows 11、Node.js 24.20.0、TypeScript 5.9.3。依赖声明沿用 [0.5.0 的显式准备方案](依赖与未构建入口验证记录.md)，没有更改外部项目的源码范围、预算、依赖版本或忽略规则。

## 修复内容

原图谱未追踪 `const { link, unlink, ... } = createReactiveSystem(...)` 返回成员的具体实现，使 `atom`、`signal` 到 `alien` 的核心调用中断。

现在注册解构绑定，并对一个受限模式追踪值来源：绑定必须是没有默认值或 rest 的 `const` 对象解构；工厂必须有唯一、同步的源码实现；函数体只能有一个直接返回的对象字面量；成员名称必须唯一且明确。支持简写函数成员、明确的函数值、内联函数及方法。不按同名、调用签名或类型断言猜测实现。

已观察到绑定、工厂或返回函数被赋值时不追踪。多返回分支、异步/生成器、展开、getter、动态成员、对象成员别名及声明文件中的类型签名保留缺口；这不是全程序数据流或运行时执行证明。

新增 `CALLS` 以 `resolution: value-origin` 标注。除调用位置的 `evidenceId`，另有 `supportingEvidenceIds` 保存解构绑定、工厂调用、返回语句和成员位置。MCP 邻域、同版本影响路径和浏览器证据面板保留这些依据，可以继续按 ID 读取保留源码与哈希。

解构参数中的函数仍是回调参数。注册参数符号后从 `unsupported` 改为 `dynamic`，不连接到某次传入的回调实现，也不将这些重分类计作已解析调用。

## 外部引用的统计口径

所有未连接到已索引目标的位置仍保留在原始快照 `unresolved` 数组，`statistics.unresolved` 和 MCP 顶层旧 `unresolved` 字段继续表示兼容总数。新字段 `resolutionSummary` 给出：

- `totalUnlinked`：兼容总数。
- `external`：目标声明位于已分析源码范围外的引用位置，包括标准库和第三方声明。统计的是位置，不是包数；依赖实现不进入图谱。
- `gaps`：其余真实解析缺口；等于 `totalUnlinked - external`。
- `byReason`：各原因的位置数，包括重分类后的动态目标。

模块或类型根本无法找到时仍计入 `unresolved`/`dynamic` 缺口，不因导入名称看起来像依赖就算正常外部引用。CLI 的 stderr 摘要、浏览器总览、节点关系和比较分别显示缺口及外部引用；MCP `symbol_context` 分为 `unresolvedDetails`、`externalReferences`，`nodeResolutionSummary` 是截断前的节点完整计数。比较的 `resolutionSummary.base/current` 分开统计。旧快照可从原始记录重新计算，无需删记录或迁移缓存来降低数字。

## 复现

先依照上一轮说明准备固定提交的专用克隆及声明，再运行：

```powershell
npm run check
npm run test:browser
npm run validate:monorepo -- --out artifacts/core-relations/self.json
npm run validate:external -- --core --baseline artifacts/core-relations/before.json
$acceptance = Get-Content artifacts/external-monorepo/latest.json -Raw | ConvertFrom-Json
node scripts/validate-resolution-reduction.mjs --before artifacts/core-relations/before.json --after (Join-Path $acceptance.run snapshot.json) --expect-external-unchanged --out artifacts/core-relations/reduction.json
npm run release
npm run verify:release
```

`before.json` 应为上述 0.5.0 完整快照，不能将含不同文件或源码哈希的结果作为对照。`--core` 选择核心工厂调用 canary；不带此参数仍执行原有 `shallow` 跨包测试调用验收。原始日志和工具结果写入被忽略的 `artifacts`，文档记录可复核的口径与结论。
