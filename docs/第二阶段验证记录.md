# CodeGraph 第二阶段验证记录

日期：2026 年 11 月 5 日

第二阶段完成本地 HTTP 服务、分析 Worker、SQLite 快照和浏览器工作台，打通“选择本地项目 → 架构概览 → 搜索 → 模块与符号导航 → 源码证据核实 → 手动刷新”的流程。

## 已交付行为

- `codegraph open <目录>` 启动回环地址上的服务，可自定义端口、自动选择空闲端口、选择缓存目录或关闭自动打开浏览器。
- 解析器运行在独立 Worker，服务保持可响应；通过 Fetch SSE 接收真实阶段，连接中断时退回任务状态轮询。
- 同一时刻一个分析任务；可取消并重试。刷新和失败不会覆盖上一份可用结果。
- SQLite 事务保存图谱与完整源码，逐文件核对哈希与证据片段，按项目隔离并保留最近三份不同内容快照。
- 架构概览按目录聚合；典型源码目录按第二层分组。概览最多显示 20 个模块，局部图最多 100 个节点，截断数量可见。
- 搜索文件、符号名与路径，按完整名称优先排序；支持多个检索词、数量上限及无结果状态。
- 模块、文件、符号的逐层导航，面包屑返回，图与列表切换，符号邻域一层或两层切换。
- 静态导入、直接调用、组件使用与候选关系分开展示，可按需加入类型和一般引用。
- 源码侧栏包含语义签名、文件路径、关联节点、未解析项、关系证据和精确位置高亮。一次读取最多 120 行，可前后翻阅。
- 输入变化每 8 秒检查一次；保留旧源码并提示过期，用户手动刷新后才切换图谱和源码版本。
- 桌面三栏、平板折叠导航、手机默认列表与单区域源码阅读；图谱节点和搜索可用键盘操作。

## 本地接口

所有 `/api/` 接口都需要本次服务的 Bearer 会话凭证，并校验 Host 与 Origin。浏览器只访问 CLI 指定的项目，分析请求不能携带其他根目录。

- `GET /api/session`：项目、最近快照与当前任务。
- `POST /api/analyses`：创建分析，重复提交时返回正在运行的任务。
- `GET /api/analyses/:id`、`GET /api/analyses/:id/events`、`DELETE /api/analyses/:id`：状态、进度与取消。
- `GET /api/snapshots/:id/overview`、`GET /api/snapshots/:id/status`：概览与当前是否过期。
- `GET /api/snapshots/:id/search`：名称和路径搜索。
- `GET /api/snapshots/:id/graph`：有数量与深度限制的图投影。
- `GET /api/snapshots/:id/nodes/:nodeId`：节点详情、邻接关系与未解析项。
- `GET /api/snapshots/:id/evidence/:evidenceId`：证据原文、位置及文件哈希。
- `GET /api/snapshots/:id/files/:fileId`：由已登记文件 ID 访问源码窗口，可按证据或符号定位。

公共类型位于 `packages/shared/src/explorer.ts`。文件接口不接收任意文件路径；前端同源静态资源由 Fastify 提供，不引入外部字体或分析服务。

## 自动验证

`npm run check` 通过：前后端生产构建成功，34 项 Node 测试通过，无失败、无跳过；第一阶段人工标注关系仍全部匹配。

新增集成验证覆盖目录聚合计数、四层导航、搜索排序与多词过滤、图规模限制、类型与候选开关、会话与来源校验、输入根目录约束、Worker 阶段、取消重试、SQLite 重新打开与不匹配源码拒绝，以及实际文件修改后仍返回旧快照源码。

`npm run test:browser` 在本机安装的 Chrome 中通过 5 条流程，最后一轮约 16 秒：

1. 从真实 fixture 生成架构，核对模块、文件和符号计数，加载本地字体并用 Enter 选择图谱节点。
2. 搜索 `normalize`，查看调用者，打开 `submit` 的调用证据并定位到 `sanitize`，验证高亮与侧栏不会被旧选择覆盖。
3. 模块到文件导航、面包屑返回、等价列表导航及搜索无结果。
4. 修改文件，确认旧图谱与旧源码仍可读；手动刷新后读取新内容，再恢复正常项目。
5. 在平板与手机宽度验证导航折叠、页面无横向溢出、目录选择与源码独立阅读。

测试始终复制 fixture 到受控临时目录，修改操作不影响仓库原始样例。Windows 中文路径、空格路径、CRLF、UTF-16、错误降级等原有验证继续保留。

## 视觉核实

采用 framed-sheet 风格，字体和图形资源随应用本地提供。生产构建分别在 1440×900、768×1024、390×844 检查，最终同一套设计探针与规则报告为零 FAIL、零 WARN。

技能自带的直接 CDP 启动器出现 `CDP socket failed`，因此改用已验证可用的 Playwright 驱动该技能原有的 `probe/frame/layout/app` 探针与规则。该替换不表示原启动器成功；本地适配脚本和完整报告保存在 `artifacts/phase-two/`，不属于产品运行依赖。

依据截图修正了共享连线路由导致的标签拥挤、视口缩小后的图谱适应、手机默认阅读方式、源码阅读边距和字号。修正了受控图谱选择事件覆盖用户证据跳转的问题，并加入键盘与证据流程回归。

主要截图：`overview-1440.png`、`source-evidence-1440.png`、`overview-768.png`、`overview-390.png`、`source-390.png`；设计测量结果位于 `design-check/report.json`。

## 运行方式与当前限制

```powershell
npm ci --ignore-scripts
npm run build
npm run open -- fixtures/reference-lab
```

按 Ctrl+C 停止服务。默认端口 4317；可用 `--port 0` 获取空闲端口。终端会打印带片段凭证的本地链接，前端载入后移除该片段。缓存默认按项目路径存入用户数据目录，可使用 `--data-dir artifacts/local-cache` 将缓存放在工作区。

当前仅支持一次服务对应一个项目，主要面向本机个人使用。目录分组不代表推断出的业务架构，结构关系不代表运行时执行顺序。复杂项目引用继续明确提示部分完成，不在本阶段扩展解析范围。

此阶段采用全量重新分析，没有增量 AST 更新；过期检查采用有上限的文件扫描，尚未对 500 文件、约 5 万行规模做重复性能验收。ELK 延迟加载的布局包约 1.46 MB、gzip 约 452 KB，后续可按大项目体验决定是否进一步拆分或迁移布局线程。

尚未提供关键代码推荐、阅读清单、AI 解释、Git 改动比较、编辑器插件或多用户访问。下一阶段沿用现有证据契约实现阅读与解释功能。
