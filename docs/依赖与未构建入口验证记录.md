# CodeTrail 0.5.0：依赖声明与未构建包入口

日期：2026-11-06。继续使用 TanStack Store 固定提交 `53f30be1e43c8d7899ace08023705b34f5e533f8`，环境为 Windows 11 / Node.js 24.20.0 / TypeScript 5.9.3。前一轮记录见 [0.4.1 外部验收](外部monorepo验收记录.md)。

## 实现

- 对已声明的工作区包，读取纳入扫描的 `tsdown.config.ts`，仅接受直接导入 defineConfig 的纯字面量配置及受限构建命令。明确的 entry、format、unbundle、dts、fixedExtension 与可选 root/outDir 建立输出到源码的唯一映射。默认 dist、入口共同目录等规则来自 [tsdown 输出目录](https://tsdown.dev/options/output-directory)及 [unbundle 配置](https://tsdown.dev/options/unbundle)。不运行配置，不支持插件、函数、展开、glob、输出钩子或命令行输出覆盖。
- 对声明了 @sveltejs/package 的工作区包，解析明确的 `svelte-package --input ... --output ...` 命令，将其中已扫描的 TS/JS 路径映射到输出。依据 [Svelte 包工具的目录与类型文件规则](https://svelte.dev/docs/kit/packaging)。`.svelte` 本身仍不解析，预处理器不执行。
- 包 exports 的条件与子路径继续由 TypeScript 选择；重复输出、跨包路径、已扫描源码碰撞及被排除的入口不猜测补齐。构建配置与 manifest 的内容参与快照身份及失效检测，分析不会生成 dist。
- 提供显式的 `prepare:external-deps` 验收准备命令。25 个框架/测试直接依赖的精确版本取自目标 pnpm 锁文件，传递依赖由另外提交的 npm 锁文件固定。npm ci 禁用脚本、忽略可选包，在隔离目录安装后复制到专用克隆；不修改目标 manifest、锁文件或源码，不构建目标。下载的是实际 npm 包，分析仅使用其声明和元数据，不索引或执行依赖实现。这不是上游完整安装，也不保证传递依赖与上游 pnpm 环境完全相同。
- 声明增多后曾触及 MCP 的 60 秒限制；该次失败不计作通过。现在在单次分析内通过 TypeScript DocumentRegistry 复用兼容的标准库/依赖声明语法树；项目源码 AST、检查器及模块解析选项保持独立，不在快照之间复用。
