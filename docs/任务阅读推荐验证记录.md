# 0.11.0 任务阅读推荐验证

日期：2026-11-09。源码基线 `583354f508611534f61b0d44b7106e7a6b85e78c`，版本 0.11.0，算法 `task-reading-3`。本轮验证推荐的任务相关性与证据流程，没有真人试用、模型生成或业务重要性评分。

## 行为与依据

默认推荐不再把入口文件中的每个顶层辅助函数都当作入口。有其他核心候选时，暂缓 examples/example、demo/demos、sample/samples、playground/playgrounds 目录；相关文件和调用仍在原始快照、搜索与图谱中。默认推荐的引用数也排除暂缓示例和原有测试/声明/生成文件。只有示例候选的项目继续正常提供阅读路线。

默认入口分别为 MCP/服务接入候选、启动名称候选和有跨目录调用依据的包接口保留机会：MCP/服务文件及名称匹配属于规则；包接口的跨模块 CALLS 有源码依据，但不证明它是运行时启动点。规则面向常见文件/目录布局，没有匹配 CodeTrail 仓库名或特定函数名来直接写死结果。

明确任务可通过 `recommend_reading({snapshotId, focusNodeIds})` 指定 1–3 个符号。先从 `search_symbols` 和源码核实 ID，沿同一快照向外两跳的静态 CALLS/RENDERS 生成路线。任务起点全部先保留，再轮流展开，核心调用先于公共辅助目录；类型引用、一般引用和回调候选不冒充调用。不能连接的阶段由任务明确选择为多个起点，不能声称它们构成一条已证实调用链。

任务路线只包含起点及其有依据的两跳关联，最多十步；不足十步不补无关节点。显式起点标为 `task-focus / rule`，关联依据标为 `task-path / static`，每个 follow 都有真实的 `fromNodeId/viaRelationId`。supplement 仍明确不表示与前一步直接相连。文件、测试、已排除声明和未知 ID 被拒绝，不静默退回全局推荐。显式选择示例符号仍可读取其路线。

返回 `scope.mode`、`scope.focusNodeIds`、`scope.deferredExampleFiles`；`excludedFiles` 继续统计原有测试/声明/生成排除，未把示例永久移出分析。MCP 内嵌证据仍最多八份，`truncated` 与现有字符预算继续有效，需按 evidenceId 补查。默认浏览器路线同步改善；任务起点目前通过 MCP 提供，未新增浏览器任务选择控件。

## 复现与边界

完整源码仓库需保留旧算法所在的 Git 提交，并先准备既有固定 TanStack 克隆及声明环境。无需将新的任务阅读参数用于旧版本服务；升级后重载 MCP 与理解项目 Skill。

```powershell
npm run check
npm run validate:reading
npm run validate:external -- --receivers
npm run test:browser
npm run validate:codex
npm run release
npm run verify:release
```

阅读脚本只读两项目并保存证据；自身影响比较使用当时真实的工作区改动，不另造临时修改。干净工作区运行时应返回零变化并跳过“阅读函数发生变化”的两侧聚焦取证；历史本次改动依据仍在对应验收目录。外部受控影响验收会恢复练习差异，不要与其他编辑/验收并发操作该克隆。

选择起点依赖 Agent/用户判断，尚不提供自然语言语义匹配；默认排序仍有常见路径、名称、公共目录规则。十步、两跳、部分解析与回调缺口仍限制结果；未展示不表示不存在关联。两项目工程验证不是一般准确率、真人耗时改善或解释质量的证明。试用标准见[小范围试用方案](用户试用方案.md)。
