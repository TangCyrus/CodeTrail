## 推荐与阅读路径

`packages/graph/src/reading.ts` 从快照计算结构线索。入口、功能链路、公共基础候选分别最多 3、4、3 项。统计不同来源文件及相邻模块，避免同一文件重复引用抬高指标；导出和实际调用关系参与排序。入口名称和公共目录属于规则候选，不输出业务重要性分数。每个理由包含来源类别和当前快照的证据 ID。

测试、fixtures、生成目录和声明文件排除在核心推荐之外。正常样例包含 `start`、`App` 等入口候选和跨文件使用的基础代码。

阅读顺序从入口候选开始，沿静态 `CALLS/RENDERS` 广度展开两层，最多 10 步并处理循环。跟随步骤记录真实关系和起点；补充条目明确说明不代表调用。回调注册候选不作为直接调用传播。

清单保存相对路径、完整符号名、种类和手动已读状态。SQLite 添加独立表，清单不依附某一快照。刷新后仅在当前快照唯一匹配时重新定位；重命名、移动或歧义会留下未定位记录，供用户整理。

## 解释与发送边界

支持解释代码、结构重要性、上下游三类问题，以及引导/紧凑两种密度。先生成绑定快照、文件哈希和位置的本地事实，再构建待发送预览。

证据从 SQLite 的快照源码读取，重新核对原片段。发送包最多 12 段证据、18,000 个 JSON 字符；字符预算不包含固定指令，也不是 token 估算。截断保留准确的 UTF-16 范围，避免拆开代理对和 CRLF。预览同时记录原始范围与实际发送范围，模型只收到展示的前缀。发送包使用相对路径，不包含项目根目录字段、服务密钥或额外文件。

预览摘要是准确序列化上下文的 SHA-256。AI 请求必须批准同一个摘要，否则返回 409。服务每次启动默认关闭 AI；启用开关和预览均不发起供应商请求。密钥从服务端进程环境读取，浏览器只访问本地服务。配置方式见 README。

原生 `fetch` 请求 `/v1/responses`，设置 `store: false`、严格 JSON Schema 输出，不提供工具。固定指令将源码、注释和名称视为分析数据。每条说明必须引用所选范围内的有效证据 ID；无效输出整份回退，不缓存为成功结果。位置校验不代表语义支持，界面保留 AI 标记、推断类别和待确认事项。

默认限制：30 秒、3,200 输出 tokens、最多 2 个并发。同一生成请求不重复并发发送。超时、取消、禁用、无证据、未配置、上游错误和无效输出均有本地回退。浏览器关闭请求也会取消上游 `fetch`；取消不能撤销供应商已经产生的用量。

有效解释按快照、内容摘要、问题、密度、模型、端点、提示版本、推理配置和输出预算缓存。数据库重开后可以复用；源码或配置变化会产生不同键。“有误”会移除相应缓存；清除缓存同时中止进行中的解释，防止旧请求回写。

接口依据：[OpenAI Structured Outputs 官方指南](https://developers.openai.com/api/docs/guides/structured-outputs)。要求明确配置当前账户可用、支持结构化输出的模型 ID，不内置默认模型。

## 新增接口

全部沿用现有会话、Host 和 Origin 校验，仅操作 CLI 已选择的项目。

- `GET /api/snapshots/:id/reading`：分组推荐和阅读顺序。
- `GET/POST /api/snapshots/:id/reading-list`：读取清单、添加当前快照节点。
- `PATCH/DELETE /api/reading-list/:key`：已读状态、移除。
- `GET/PATCH /api/ai`：无密钥的配置状态、本次服务启用开关。
- `POST /api/snapshots/:id/explanations/preview`：证据预览、文件范围和摘要。
- `POST /api/snapshots/:id/explanations`：本地或 AI 解释；AI 需批准预览摘要。
- `DELETE /api/ai/cache`：取消进行中解释并清除结果缓存。
- `POST /api/explanations/:resultId/feedback`：有帮助/有误反馈。
