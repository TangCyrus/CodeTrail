# 第六阶段：本地 MCP、Skill 与首个 Agent 宿主

日期：2026-11-06。版本：0.2.0。环境：Windows 11、Node.js 24.20.0、npm 11.19.0、Git 2.55.0.windows.5、Codex CLI 0.166.0-alpha.6。

## 交付范围

已将 CodeGraph 的主接入方向调整为 Coding Agent 工具层。新增 `apps/local/src/mcp.ts` 和 `codegraph mcp <directory>`，采用官方 MCP TypeScript SDK 2.4.0，支持本地 stdio。宿主启动进程时固定一个真实项目根目录，工具参数不能切换根目录。

六个工具为 project_overview、search_symbols、symbol_context、read_evidence、recommend_reading、compare_worktree，直接复用 AnalysisManager、ComparisonManager、SnapshotStore、ProjectExplorer 与 recommendReading。另提供只读 `codegraph://guide` 资源。没有重新实现一套解析或影响传播逻辑。

普通快照查询固定 snapshotId；比较取证固定 comparisonId 与 base/current，保留文件哈希及行范围。结果给出部分解析、未解析、过期与截断信息。服务不执行目标代码、不修改 Git/源码、不调用模型，内部缓存保存纳入分析的源码。

默认不监听 HTTP；`--workbench` 可开启同进程、同快照的回环证据工作台。该模式的内置 AI 未配置且关闭。源码通过 MCP 进入宿主上下文后的发送受宿主配置控制，不能称为完整离线 Agent。

`skills/codegraph-understand` 与 `skills/codegraph-impact` 包含实际工作流、版本与来源校验、取证方式、不可信源码处理及失败降级。`scripts/setup-codex.mjs` 生成配置和 Skill 接入包，拒绝覆盖已有输出，不修改用户 Codex 配置。

## 自动测试

`npm run check` 通过：**82 项 Node 测试，零失败**，包含新增 12 项 MCP 验证；日志在 `artifacts/phase-six/check.log`。

新增 MCP 测试覆盖：

- 官方客户端真实启动 stdio 进程、初始化、发现六个工具、架构→搜索→关系→源码→阅读推荐完整查询。
- 源码中的伪指令保留为明确标记的不可信数据；此测试验证数据处理，不证明模型能抵抗注入。
- 编辑后旧快照过期、源码哈希不再匹配，但旧原文仍可读取；显式刷新获得新版；历史 ID 不自动替换。
- 根目录覆盖、越界图范围/页大小、任意文件路径、无效 ID、混用版本选择器均被拒绝。
- Git 分页、旧新同侧路径证据、已删除旧文件取证、新版无该文件时拒绝；比较前后 HEAD 和 Git 索引字节保持不变。
- 无 Git、无 HEAD 分别降级；普通阅读仍可使用。
- 长源码行截断、有效 JSON 与结果字符上限；快照超过保留数量后明确返回 NOT_FOUND。
- 可选工作台共用同一快照、未经认证拒绝、内置 AI 未启用且未配置。
- 服务期限触发、中途 MCP 取消后重试、stdio EOF 时结束正在运行的分析并退出。
- 中文/空格路径的接入包生成、两个 Skill 随包提供、拒绝覆盖。
- 语法错误保持 partial，动态关系保留未解析事实。

原解析金标准继续通过：IMPORTS 13、CALLS 18、RENDERS 1、REGISTERS_CALLBACK 2、指定 REFERENCES 8、UNRESOLVED 6，标注范围内 FP/FN 均为零。该结果不是总体准确率。

两个 Skill 均通过 skill-creator 的 quick_validate.py 校验。当前 Python 缺少 PyYAML，验证依赖安装在 `artifacts/phase-six/python-deps`，没有改动全局 Python 环境。Codex 也实际读取了两者的元数据，未返回 Skill 加载错误。

## Codex 宿主验收

执行 `npm run validate:codex` 成功。脚本启动真实 Codex app-server，使用独立 CODEX_HOME、自有 Git 演示项目和项目范围的两个 Skill，不复用用户配置或凭据。只创建隔离的临时协议上下文，不启动模型生成。

验收通过宿主的 skills/list、thread/start、mcpServerStatus/list 与 mcpServer/tool/call 进行；六个工具全部由 Codex 发现，运行状态 connected，两个 Skill enabled 且加载错误为空。

实际工具调用九次：概览、搜索、符号关系、普通源码、阅读推荐、首次比较、旧版路径取证、编辑后检查过期、刷新比较。最大单次结构化结果 31,748 个 JSON 字符，低于 48,000 字符上限。这是代表样例的一次结果大小，不是全部项目的性能或上下文节省结论。

机器记录：`artifacts/phase-six/codex-acceptance.json`。该文件的 run 指向本次独立目录，包含 skills-discovery.json、host-inventory.json、tool-calls.json 与 host-stderr.txt。宿主可能自行尝试插件目录同步等后台请求；验收网络限制下的相关警告与 CodeGraph 工具无关，不宣称整个宿主零网络请求。CodeGraph 只实现 stdio 和可选本机工作台，无模型或外部服务调用。

**边界：调用由确定性验收脚本选择。尚未验证真实模型是否正确选工具、遵循 Skill、抵抗源码注入，或准确解释业务。** 因而本阶段结论是宿主接入与核心工具链路已通，不是模型行为或用户价值已获验证。

源码入口和独立预编译包均包含 MCP、Skill、接入包生成器与 Agent 接入说明。0.1.0 历史包保持不变，不含这些能力。0.2.0 包的生产依赖通过锁文件安装，Node/Git 仍由本机提供。

## 后续待验

- 在真实开发任务中观察 Agent 是否选择合适的查询，以及是否正确读取过期、截断与证据版本。
- 比较普通搜索与图谱辅助在任务耗时、源码引用准确性和上下文消耗上的差异。
- 用实际模型评测 Skill 工作流和源码指令注入场景，不把提示要求本身当作安全保证。
- 首个宿主为本机 Codex 的指定版本；其他宿主、宿主版本、操作系统尚未完成同等验收。
- 当前生成接入包后需合并配置并安装 Skill；市场插件、自动配置安装、远程 MCP、多项目路由与增量索引不在本阶段范围。
