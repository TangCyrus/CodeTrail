# CodeTrail MVP 已知限制

版本：0.11.0 本地 Agent 接入试用版。真实公开 monorepo 的固定提交验收见 [TanStack Store 验证记录](外部monorepo验收记录.md)；独立团队使用效果和真人任务试用尚待验证。

0.3.0 统一使用 CodeTrail 命名，旧命令、旧环境变量及旧忽略文件名不再作为入口，升级步骤见 [命名迁移说明](命名迁移说明.md)。历史缓存保留，不自动迁移或删除。

## Agent 接入

- 仅实现本地 stdio MCP，固定一个项目根目录；尚未实现远程 HTTP MCP、自动多项目路由或市场插件发布。
- 首个宿主实际验证为 Windows 下 Codex CLI 0.166.0-alpha.6 的 app-server，0.8.0 在 0.167.0-alpha.3.2 再次复验。Cursor、Claude Code 等尚未完成同等接入验收，不能仅凭协议通用性宣称已支持。
- 验证了宿主发现 Skill、六类工具和实际工具调用；验收脚本选择调用，不启动模型生成。尚未测得模型自主工具选择、Skill 行为效果、提示注入抵抗或业务解释质量。
- MCP 返回的源码进入宿主上下文，可能由宿主发往模型。CodeTrail 自身无模型调用，不等于宿主完全离线。缓存包含纳入分析的完整源码。
- 单个 MCP 结果最多 48,000 个 JSON 字符；源码窗口最多 80 行、12,000 字符，单行 2,000 字符。邻域最多两跳、40 节点、40 组边，默认只内嵌八份证据；应按 ID 继续取证。超大结果返回错误后需要缩小查询。
- 影响查询最多两跳、100 条路径、20,000 次边检查；概览每侧最多 200 个起点，轮流分配路径，不能保证所有关键链都在概览中。按符号聚焦从保存的指定版本图独立追踪，避开概览起点/路径预算，但仍受自己的路径、深度及工作量限制，每个起点/目标仅保留一条最短依据。文件变化摘要与声明映射也可能截断；符号搜索覆盖变化文件的完整保存声明，不受摘要和概览起点限制。分页不解除分析预算，详见 [路径聚焦验证](路径聚焦验证记录.md)。
- 服务期限 60 秒，查询串行。`--workbench` 共享相同管理器及快照，浏览器刷新也会更新缓存；每次结论仍应固定 ID 并核对过期状态。
- 接入包生成器不修改现有宿主配置。合并配置和复制 Skill 后仍需宿主加载；绝对路径随安装或项目移动而需要更新。

## 环境与安装

- 正式复验环境为 Windows 11、Node.js 24.x、npm 11+、本机 Chrome。预编译包仍需要 Node，不包含 Node/Git 安装程序。
- macOS/Linux、其他 Node 主版本及其他浏览器没有完成同等验收。打包与解压冒烟脚本当前针对 Windows。
- 首次源码安装需要 npm 网络；预编译包的本地阅读不依赖外网。Git 比较需要本机 Git；AI 是单独配置的可选外部服务。

## 范围与解析

- 只扫描 `.ts/.tsx/.js/.jsx`，默认 500 个源码文件、每个最多 1 MiB。`.mjs/.cjs`、其他语言和二进制源码暂不支持。
- 源码需为有效 UTF-8，可以保留 BOM。非法编码、大小限制或不可读文件会明确跳过，其他健康结果保留。
- 所选根目录限定源码和配置边界；不隐式扩展到父目录，不跟随源码目录链接。根目录内最多处理 64 个项目配置和有界引用，按就近目录及文件归属选择选项；源码仍限于扫描 allowlist。
- 支持 npm workspaces 数组/对象、根 pnpm-workspace.yaml 的 packages 字面量列表、引用项目中的具名包，以及 TypeScript 的 exports 条件、子路径与路径别名。pnpm 配置存在时优先于 npm workspaces；支持常用相对 glob 与排除模式，YAML 最多 64 KiB、256 项、每项 512 字符，包列表中的别名、自定义标签、非法/跨根模式保留诊断。仅识别工作区身份，不执行或套用 allowBuilds、catalog、安装策略和自定义钩子；Yarn PnP 未实现。
- 未构建入口可由唯一的 rootDir/outDir/declarationDir、有限的 tsdown 静态配置，或声明了 @sveltejs/package 的显式 `svelte-package --input ... --output ...` 命令映射到已扫描源码。tsdown 只支持纯字面量 defineConfig、明确的 entry/format/unbundle/dts/fixedExtension 设置、可选 root/outDir；命令仅允许 tsdown 及可选 --tsconfig。插件、函数、展开、glob、输出钩子、CLI 覆盖、路径冲突及其他构建工具保留缺口，不执行配置或按 src/index 惯例猜测。
- 第三方声明仍归为 external，不索引依赖实现；单独分析子包时，位于选定根目录之外的兄弟包和共享配置仍不会被读取。多种编译环境会增加分析时间和内存，不能把单上下文性能数据直接外推到所有 monorepo。
- 不执行 Vite 等配置、编译器插件、目标项目脚本或依赖安装。目标依赖声明缺失时类型与模块解析可能不完整。
- 依赖声明需要先在选定根目录内准备；MCP/分析器不联网下载、不生成 any 声明替身。源码验收提供显式 `npm run prepare:external-deps`，按独立锁定方案为专用 TanStack Store 克隆安装真实依赖包，禁用安装脚本与目标构建。该方案覆盖选定框架/测试声明，直接版本来自目标锁文件，传递依赖采用独立 npm 锁；不等于上游完整安装。历史 HEAD 仍不复用工作区未提交的依赖，双侧环境差异会在报告中保留。
- CommonJS、动态模块导入、复杂解构、独立构造器调用节点、私有方法及完整数据流尚未覆盖。匿名回调、动态分发、`any` 和歧义目标保留缺口。
- 简单工厂返回函数的 `const` 对象解构支持有界值来源追踪；默认值/rest、异步/生成器、多个返回、对象展开/getter、观察到的赋值和动态成员等不追踪。不把接口方法签名、参数回调或类型断言当成实际实现；新增静态调用也不证明运行时执行。
- `external` 指目标声明位于分析源码范围外，单独显示位置数，不能当成依赖包数量或解析缺口。旧原始 `unresolved` 数组及旧统计仍含外部引用，使用新增 `resolutionSummary.gaps/external` 区分；缺失的依赖声明继续是实际缺口，不以导入名称推测为正常外部引用。当前验证见 [核心调用与外部引用](核心调用与外部引用验证记录.md)。
- 调用、符号引用、组件使用和纯类型依赖分别记录；静态调用不能证明实际执行，回调注册候选不能当作发生的调用。
- 对象/接口方法追踪明确字面量、const 别名及有唯一直接返回的新建工厂对象；0.8.0 增加内联嵌套对象、简单子对象解构、封闭对象自有方法的 this、方法内 const self 别名及箭头函数的词法 this。沿父子路径核对写入和逃逸，不按接口或成员名称匹配实现。成员/父路径写入、动态名称、默认值/rest、访问器/展开、共享子对象、未知逃逸及方法脱离接收者仍保留原因和源码依据。单次来源最多 12 层、128 个对象/别名、1,024 个引用；达到上限保留缺口。
- 不跨不同工厂实例合并方法体 this；类继承、普通回调、参数接收者、容器点集及跨参数上下文仍未实现。嵌套方法的显示名称可能省略非函数属性层级，应以节点 ID、文件位置与证据区分同名项。详见 [this 与嵌套别名验证](this与嵌套别名验证记录.md)，此前结果见 [对象分发验证](对象分发验证记录.md)。
- 原生 bind 仅追踪具有唯一源码函数体、未观察到写入/暴露的私有函数及绑定结果 const 别名，支持唯一同步直接返回的绑定工厂；创建绑定不等于执行函数。原生 call/apply 可补充到源码函数体的调用，原有标准库外部引用仍保留，不能把新增边算成缺口消除。箭头函数绑定不替换词法 this，也不利用绑定参数为普通函数体全局固定 this。构造调用、Proxy/eval、原型反射及扫描范围外的内建方法改写未建模；观察到的 bind 改写、未知函数暴露及不明确来源保留缺口。这是有界静态关系，不能保证运行时行为。

## 推荐与图谱

- 推荐根据名称、目录、导出及不同文件/模块的静态关联提供结构线索，不推断业务优先级。
- 推荐最多 10 项；阅读顺序最多 10 步、沿两层真实关系，不表示执行顺序。测试与生成目录等排除在核心推荐之外。
- 0.11.0 默认在存在非示例候选时暂缓 examples/demo/sample/playground 目录，也不把其中的引用计入默认结构指标；文件仍保留在普通搜索与图谱。只有示例候选的项目可正常推荐，指定任务起点可显式选择示例。目录命名和 MCP/服务入口规则都可能不适合非常规布局，不能证明业务重要性。
- MCP 任务阅读需要 Agent 先选择当前快照的 1–3 个符号，不提供自然语言任务语义匹配。路线仅包括这些起点及两跳向外的已解析 CALLS/RENDERS，不追踪反向调用者或拼接断开的架构阶段；不足十步不补无关候选。多个起点先保留再轮流展开，仍受十步与两跳限制。来源及对照见[任务阅读验证](任务阅读推荐验证记录.md)。浏览器使用默认排序，任务起点参数目前通过 MCP 提供。
- 默认局部图最多 100 节点、两层邻域。大范围会截断，应结合搜索和列表导航核实；没有列出不表示没有关联。
- 自动布局在独立 Worker 中运行，超过 2 秒或加载失败时中止并回退网格；这时应结合列表阅读，不保证复杂稠密关系仍有清晰的层级排布。
- 阅读记录跨快照仅按完整名称、种类和相对路径唯一匹配；移动、改名或歧义可能需要人工重新加入。

## Git 比较

- 仅支持 HEAD 与工作区实际内容，不提供任意提交或分支比较。两侧分别保存源码，旧新版边不会拼接。
- 文件重命名只提供候选。提示来自暂存区对象相似度或唯一原文哈希；未暂存且内容变化的移动可能显示为删除/新增。符号改名不猜测合并。
- 只改变换行编码不计为代码变化；其他文本变化仍可能只是格式变化，并不表示业务行为变化。
- 历史项目源码和配置只读取 Git 已提交的普通源码、JSON、根 pnpm-workspace.yaml/pnpm-lock.yaml 和忽略配置。可从当前分析读取集捕获辅助声明/JSON：包名、安装版本及旧新锁文件包身份需匹配，文件哈希需与分析时一致；不安装历史依赖、不执行配置、不复制依赖实现或工作区生成的声明替代 HEAD 源码。声明捕获不是历史 node_modules 重建，也不是包压缩包完整性验证，详见 [HEAD 依赖环境验证](HEAD依赖环境验证记录.md)。
- 声明捕获支持 npm lock v2/v3 和最多八文档的 pnpm lock v9；重复身份、版本/完整性记录不匹配、链接安装布局、缺失或不支持的锁保留明确原因。每次最多 4,096 文件、32 MiB，单文件/锁最多 1 MiB。只覆盖当前分析已读声明，HEAD 独有依赖、不同条件导出及安装差异仍可能缺失；state available 不等于基线解析完整。两侧诊断仍独立显示。
- 历史物化最多 2,000 个候选文件、合计 64 MiB、单文件 1 MiB；默认传播最多两跳、100 条路径，声明和行差异也有明确预算。
- 文件级导入是保守关联；配置变化导致的全部语义变化不穷举。测试文件静态关联不表示测试覆盖、运行成功或已发生故障。
- 大仓库双图比较需要解析和保存两个版本，还包含 Git 对象读取；其耗时单独报告，不与缓存搜索耗时混为一谈。

## 缓存与失败

- 普通分析和比较分别保留最近三份，旧结果清理后不能继续打开对应源码。缓存含本地和历史源码，按项目路径隔离。
- 缓存损坏时停止该缓存的读取并给出新目录指引，不自动修复或清空。异常强制退出可能留下临时文件。
- 变化检查每 8 秒进行一次，存在观察间隔；刷新由用户触发，不提供增量后台重建。
- 分析状态 `complete` 表示本次解析没有错误/警告，不代表图完整；`partial` 和未解析数量都需结合查看。

## AI 与验收证据

- 模型需明确配置并支持 Responses JSON Schema。结构化响应、引用身份、取消和故障回退使用本地模拟服务验证；未进行真实模型语义支持率评测。
- 引用有效只证明位置在发送范围内，不能自动证明解释含义正确。推断与不确定项需要结合源码判断。
- 自动样例和合成性能工作负载不能外推真实项目准确率。人工标注只覆盖公开列明的位置，不承诺总体关系精确率或召回率。
- 尚无 3 位新手和 3 位熟练开发者的实际试用数据，不宣称理解耗时减少 30%。可按[试用方案](用户试用方案.md)、[任务卡](试用任务卡.md)、[评分标准](试用验收标准.md)与[反馈模板](用户试用反馈模板.md)组织；[两项目工程预跑](试用预跑记录.md)只验证工具流程，反馈和真人成绩应在真实使用后填写。
