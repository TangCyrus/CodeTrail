# CodeGraph 第一阶段验证记录

日期：2026 年 11 月 5 日

第一阶段已完成工程骨架、TS/JS 代码解析原型和符号引用关系验证。当前交付是可运行的 CLI 与 JSON 图谱，后续界面可以直接消费共享契约。浏览器界面、Worker 调度服务、数据库持久化和 Git 改动比较尚未实现。

## 交付内容

- npm workspaces 工程，包含 `apps/local`、`apps/web`、`packages/shared`、`packages/analyzer`、`packages/graph`。
- 固定 TypeScript 5.9.3；编译器对象隔离在分析适配器内，跨包只传递通用快照契约。
- 文件范围扫描、忽略规则、文件限制、输入哈希、编译诊断和过期检测。
- 符号、静态导入、直接调用、引用、JSX 组件使用、回调参数候选及对应源码证据。
- 正常样例 `reference-lab`、降级样例 `degraded-lab`，以及独立维护的人工关系清单。
- 带方向、深度和数量限制的反向依赖查询，用于提前验证影响路径的基本语义。
- 原子输出 JSON 的 CLI、25 项测试与可重新生成的验证报告。

## 复现方式

在仓库根目录执行：

```powershell
npm ci --ignore-scripts
npm run check
npm run analyze -- fixtures/reference-lab --out artifacts/reference-lab.json
npm run analyze -- fixtures/degraded-lab --out artifacts/degraded-lab.json
```

分析器自身代码的冒烟检查：

```powershell
npm run analyze -- . --out artifacts/self-analysis.json
```

项目根目录的 `.codegraphignore` 会排除用于验证的 fixture，避免故意损坏的样例混入工具自身源码图。

## 人工标注验证结果

正常样例包含 14 个源码文件。最后一次完整检查中：

- `IMPORTS`：13 处标注全部匹配，FP 0、FN 0。
- `CALLS`：18 处标注全部匹配，FP 0、FN 0。
- `RENDERS`：1 处标注匹配，FP 0、FN 0。
- `REGISTERS_CALLBACK`：2 处回调参数候选匹配，FP 0、FN 0。
- `REFERENCES`：8 个指定引用位置全部匹配，FP 0、FN 0。未据此评价样例中其余引用。
- `unresolved`：6 处均与预期匹配，包括可调用参数、any、无法确定函数体的变量、属性回调，以及动态属性引用。

前四类按整个正常样例的出现位置清单比对，使用多重集合计数，重复生成的关系也会计为误报。验证门禁另外检查“额外插入关系”和“遗漏关系”会被发现，避免只检验已预期的正例。

本样例规模很小，标注一致性只能证明这些明确场景得到正确处理，不能推导真实仓库的总体精确率、召回率或运行时覆盖率。规则候选的匹配也不表示已发生回调执行。

## 测试覆盖与实际修复

`npm run check` 中 25 项测试通过，无失败、无跳过。覆盖内容包括：

- 同名函数、嵌套作用域、导入别名、路径映射、转导出、重载实现与 JS 消费。
- 回调候选、内联回调独立所有者、立即执行函数、类箭头函数字段与联合类型歧义。
- 类型和值关系、类继承、接口实现、独立导出声明和对象参数签名。
- 证据片段逐字核实、行列映射、UTF-16、CRLF、中文与空格路径。
- 配置损坏、源码语法错误、缺失模块、被忽略模块、嵌套忽略规则及文件限制。
- 选定目录之外的目录链接被拒绝；根目录内依赖声明链接可解析，其变化会使快照标识失效。
- 源码、配置脚本与依赖实现不执行；CLI 参数错误、纯 JSON 输出与原子写入。
- 反向依赖方向、类型关系开关、循环终止、深度与数量截断及证据路径连续性。

验证过程中修复了三个关键问题：局部变量初始化中的调用归属于外层函数；损坏 tsconfig 的 Windows 路径规范化；根目录内工作区依赖声明经真实路径解析后的读取与缓存失效。还避免把类的运行时继承误标成纯类型依赖。

## 初步耗时与环境

测试机器为 Windows x64，Intel Core i7-14700，32 GiB 内存；Node.js 24.20.0、npm 11.19.0。正常样例为 14 个源码文件，降级样例为 3 个源码文件。

具体耗时记录在 `artifacts/phase-one-validation.json` 的 `fixtures[].statistics.durationMs`。当前这批小样例单次分析在亚秒范围内；该测量包含扫描、编译器上下文、关系提取、证据和输入复核，不包含 npm 启动、JSON 写入或任何 AI 工作。

这只是小样本单次计时，受进程缓存与文件系统缓存影响，尚未完成 500 文件或约 5 万行目标规模的重复性能测试，也不据此宣称达到 MVP 的规模验收预算。

工具自身源码扫描可输出快照；由于根配置含有项目引用，它会明确返回 `partial` 和 `PROJECT_REFERENCES_UNSUPPORTED`。这是对跨项目配置能力的边界提示，不能当作 monorepo 已完整支持。

## 下一阶段入口与剩余边界

下一阶段可以围绕 `AnalysisSnapshot` 接入本地服务、Worker、SQLite 和模块聚合，再实现架构导航、搜索、图与列表及只读源码侧栏。

接入界面时必须沿用三项约定：`complete` 不代表关系完备；`REGISTERS_CALLBACK` 始终展示为候选；每次源码跳转均绑定文件哈希和快照。静态反向关系查询也不能直接命名为“已受影响”或“已发生故障”。

当前原型采用单编译上下文，tsconfig 仅提供编译选项，扫描范围由文件允许清单和忽略规则决定。复杂项目引用、框架动态路由、跨进程关系和完整数据流仍需后续专门适配。
